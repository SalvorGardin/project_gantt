# Развёртывание

Статический сайт без сборки. Предварительная конфигурация: `deploy/Caddyfile`. Caddy получает и продлевает сертификат автоматически. Применять после проверки ОС, DNS, портов и существующих сервисов; не заменять конфигурацию работающих сайтов целиком.

Источники: https://caddyserver.com/docs/install и https://caddyserver.com/docs/automatic-https .

## Диагностика на сервере

```sh
ssh -p 2620 admin_user@179.253.173.110
cat /etc/os-release
id
sudo -n true
sudo ss -ltnp
command -v caddy
command -v nginx
```

## DNS

В DNS-зоне домена нужна A-запись `@` → `179.253.173.110`. Если AAAA существует, она должна вести на IPv6 этого же сервера; неверная AAAA помешает доступу и выпуску сертификата. Существующие CAA должны разрешать выбранный Caddy центр сертификации. Поддомен www пока не настраивается.

## Публикуемые файлы

В `/srv/onlinegantt` копировать только:

```text
index.html
style.css
app.js
js/project-file.js
js/powerpoint-export.js
```

Веб-серверу достаточно прав чтения. Перед обновлением сохранить предыдущую версию каталога и конфигурацию для отката. Не копировать репозиторий целиком в публичный каталог. Сетевой доступ к CDN и шрифтам необходим браузерам посетителей.

## Проверка на сервере и снаружи

После установки Caddy и подготовки файлов проверить конфигурацию через `sudo caddy validate --config /etc/caddy/Caddyfile`, затем применить через `sudo systemctl reload caddy`. При первоначальной настройке проверить, что сервис включён и запущен. Проверить `systemctl status caddy` и `journalctl -u caddy`, HTTPS и редирект HTTP через curl, ответы 404 для служебных файлов, затем сценарии приёмки в браузере. При ошибке вернуть предыдущие файлы/конфигурацию и повторить проверку перед reload.

## Статус проверки 12 ноября 2026

SSH на 2620 доступен. Ubuntu 24.04.5 LTS, Caddy 2.11.9 active/enabled. Фактический /etc/caddy/Caddyfile совпадает с deploy/Caddyfile; caddy validate проходит. Caddy слушает TCP 80/443 и локальный admin endpoint 127.0.0.1:2019. Другие веб-сервисы не обнаружены. UFW отключён; локальный DNS слушает loopback. Парольная SSH-аутентификация отключена в доступном drop-in. Полная эффективная конфигурация SSH и системные журналы без sudo не проверены.

RAM 961 MiB, доступно около 623 MiB; диск 96 GiB, свободно около 94 GiB, swap отсутствует. ОС сообщает о требуемой перезагрузке; перезагрузка не выполнялась.

Пять файлов /srv/onlinegantt принадлежат root, доступны на чтение и побайтно соответствуют текущему проекту по SHA-256. Повторная запись и изменение конфигурации не выполнялись. sudo -n требует пароль; системные журналы Caddy текущему пользователю недоступны.

DNS: NS ns1.reg.ru/ns2.reg.ru, A 95.163.244.138, AAAA и CAA отсутствуют в ответах резолвера сервера. Домен возвращает парковочную страницу REG.RU через openresty. Требуется изменить A для @ на 179.253.173.110. Локальный Caddy отвечает HTTP 308 на HTTPS, но TLS с правильным SNI пока завершается internal error. Наличие доверенного сертификата не подтверждено.

55 Node-тестов прошли. Браузерная приёмка на публичном домене ожидает исправления DNS. Изменение архивировать после завершения приёмки.
