## Why

Первый этап harden-project-boundaries: исправить импорт и защитить план от потери при замене, отмене и ошибке загрузки.

## What Changes

- Общая строгая подготовка JSON v1 для обеих точек импорта, до изменения диаграммы.
- Нормализация идентификаторов, проверка дат, ссылок и циклов; безопасный вывод импортированного текста.
- Откат при ошибке применения данных, подтверждение замены изменённого проекта, отмена нового проекта без очистки старого.
- Учёт изменения имени и перестановок, новый проект сразу имеет признак несохранённых данных.
- Сохранение названий и типов связей при повторном импорте, проверка перед экспортом JSON.

Экспорт PNG/JPEG, переработка пересчёта родителей, CDN и iframe-интеграция остаются отдельными задачами исходного предложения.

## Capabilities

### Modified Capabilities

- project-files: проверка и безопасная загрузка/сохранение.
- project-session: отмена и подтверждение замены, dirty-флаг.
- dependencies: нормализация ID и сохранение типов при загрузке.
- timeline-view: текст файлов не интерпретируется как HTML.

## Impact

Один обычный script-модуль проверки файлов без зависимостей; способ запуска и JSON v1 сохраняются. Неверные файлы отклоняются с указанием поля. Нового сборщика и backend нет.
