# Веб-приложение для дорожной карты проекта в виде диаграммы Ганта

## Назначение
Приложение предназначено для планирования и визуального ведения дорожной карты проекта в формате диаграммы Ганта. Оно должно позволять создавать иерархию из групп задач, задач, подзадач и вех, редактировать сроки и связи, а также визуально управлять структурой плана через drag-and-drop. Базовыми требованиями для современного Gantt-интерфейса считаются перетаскивание задач, линии зависимостей, масштабирование таймлайна и отзывчивый интерфейс, поэтому эти возможности стоит включить в MVP [1].

## Цели продукта
- Дать команде единый визуальный план проекта с временной шкалой.
- Упростить управление структурой работ: фазы, задачи, вложенные задачи, контрольные точки.
- Обеспечить быстрое изменение порядка задач и зависимостей без ручного редактирования структуры.
- Позволить сохранять проект в файл и загружать его обратно без сервера как минимум на первом этапе.
- Подготовить архитектуру, которую позже можно расширить до многопользовательского режима.

## Пользовательские сценарии
1. Пользователь создает новый проект и задает его название.
2. Пользователь добавляет группу задач, например «Аналитика», «Разработка», «Запуск».
3. Внутри группы он создает задачи и подзадачи, указывает даты, ответственного, цвет и иконку.
4. Пользователь связывает задачи зависимостями, чтобы отразить порядок выполнения. В Gantt-системах типовые зависимости обычно включают finish-to-start, start-to-start, finish-to-finish и start-to-finish [2].
5. Пользователь перетаскивает задачи мышью, меняет порядок и при необходимости вложенность.
6. Пользователь добавляет вехи для ключевых контрольных точек проекта; практика планирования рекомендует структурировать проект через задачи, подзадачи и milestones по фазам [3][4].
7. Пользователь сохраняет проект в локальный файл и позже загружает его обратно.

## Границы MVP
### Входит в MVP
- Один проект, открытый в одном окне браузера.
- Древовидная структура: группа, задача, подзадача, веха.
- Отображение на временной шкале в виде диаграммы Ганта.
- Перетаскивание задач для изменения порядка.
- Редактирование свойств задачи.
- Создание и удаление зависимостей.
- Сохранение в файл JSON.
- Загрузка проекта из JSON.
- Интерфейс на Bootstrap.
- Backend на Python.

### Не входит в MVP
- Совместная работа нескольких пользователей.
- Авторизация и роли доступа.
- Хранение проектов в базе данных.
- Интеграции с Jira, ClickUp, GitHub и календарями.
- Отдельный мобильный интерфейс как нативное приложение.

## Технологический стек
| Слой | Предлагаемый стек | Обоснование |
|---|---|---|
| Backend | Python 3.12 + Flask или FastAPI | Легкий сервер для отдачи UI, API и импорта/экспорта проекта |
| Frontend | HTML + Bootstrap 5 + vanilla JS | Bootstrap закрывает базовую UI-сетку и формы |

| Формат файла | JSON | Простой переносимый формат для сохранения дерева задач и связей |

## Концепция интерфейса
Экран делится на три основные области:
- Верхняя панель: название проекта, кнопки «Новый», «Сохранить», «Загрузить», выбор масштаба времени.
- Левая панель: иерархический список элементов проекта.
- Правая панель: временная шкала и полосы диаграммы Ганта.

Дополнительно нужен выезжающий редактор задачи или модальное окно Bootstrap для изменения полей выбранного элемента.

## Функциональные требования
### 1. Управление структурой проекта
- Создание группы задач.
- Создание задачи внутри корня или группы.
- Создание подзадачи внутри задачи.
- Создание вехи внутри группы или рядом с задачами.
- Переименование любого элемента inline или через форму.
- Удаление элемента с подтверждением.
- Каскадное удаление дочерних элементов или перенос детей на уровень выше — поведение должно быть определено в UX.

### 2. Порядок и вложенность
- Пользователь может менять порядок элементов drag-and-drop.
- При перетаскивании система показывает допустимую позицию вставки.
- Нужно определить два режима DnD:
  - изменение порядка внутри одного родителя;
  - перенос в другую группу или задачу с изменением `parent_id`.
- После переноса автоматически пересчитывается `sort_order`.

### 3. Редактирование свойств задачи
Для группы, задачи и подзадачи:
- Название.
- Цвет.
- Дата начала.
- Дата окончания.
- Ответственный.
- Иконка-смайлик.
- Описание/заметки.
- Статус.
- Прогресс.

Для вехи:
- Название.
- Дата.
- Цвет.
- Ответственный.
- Иконка-смайлик.
- Описание.

### 4. Работа со сроками на диаграмме
- Задачи отображаются полосами, вехи — ромбами.
- Перетаскивание полосы меняет период задачи.
- Растягивание краев полосы меняет дату начала или окончания.
- Изменения сразу синхронизируются с левой таблицей.
- Масштаб шкалы: день, неделя, месяц, квартал. Поддержка zoom controls считается одной из базовых возможностей Gantt-компонента [1].

### 5. Зависимости
- Пользователь может создать связь между двумя задачами.
- Должны поддерживаться как минимум типы `FS`, `SS`, `FF`, `SF` [2].
- Связи отображаются линиями на диаграмме.
- При удалении задачи связанные зависимости либо удаляются автоматически, либо помечаются ошибкой валидации.
- Желательно добавить визуальное создание связи мышью, так как drag-create dependency является типовым UX-паттерном для Gantt [6][7].

### 6. Сохранение и загрузка
- Кнопка «Сохранить в файл» выгружает проект в JSON.
- Кнопка «Загрузить из файла» импортирует ранее сохраненный JSON.
- При загрузке выполняется валидация версии формата.
- При несовместимом формате пользователь получает понятное сообщение об ошибке.

### 7. Представление данных
- Левая часть показывает дерево элементов.
- Правая часть показывает календарную сетку и графические элементы.
- Выбранный элемент подсвечивается в обеих областях.
- Поддерживаются сворачивание и разворачивание групп и задач с детьми.

## Предлагаемые базовые функции, которых сейчас не хватает
Ниже функции, которые обычно полезны даже в первой версии и логично добавить в спецификацию.

| Функция | Зачем нужна |
|---|---|
| Процент выполнения | Позволяет использовать Gantt не только как план, но и как трекер прогресса |
| Статус задачи | Нужен для быстрых фильтров: в работе, завершено, блокировано |
| Масштаб времени | Без переключения день/неделя/месяц диаграмма быстро становится неудобной [1] |
| Сворачивание/разворачивание веток | Критично для больших планов с подзадачами [3] |
| Валидация дат | Предотвращает задачи, у которых окончание раньше начала |
| Фильтр и поиск | Ускоряет работу с большими проектами |
| Undo/redo | Полезно из-за активного drag-and-drop и редактирования |
| Автопрокрутка к текущей дате | Удобно при открытии длинного плана |
| Подсветка просроченных задач | Повышает управляемость плана |
| Настройка нерабочих дней | Делает сроки ближе к реальности |

## Нефункциональные требования
### Производительность
- Интерфейс должен комфортно работать минимум с 500 элементами без заметных лагов.
- Перетаскивание не должно блокировать основной UI-поток более чем на 100 мс на действие.

### Удобство
- Все основные действия доступны мышью без перезагрузки страницы.
- Формы редактирования должны быть короткими и понятными.
- Цвет и эмодзи должны сразу отображаться в списке и на диаграмме.

### Надежность
- Перед сохранением данные валидируются.
- Некорректный импорт не должен ломать текущее состояние приложения.
- Желательно предупреждение о несохраненных изменениях при закрытии страницы.

### Поддерживаемость
- Разделение на слои: модель данных, операции редактирования, визуализация, импорт/экспорт.
- Формат файла должен иметь поле `schema_version`.

## Архитектура приложения
### Вариант для MVP
- Python-сервер отдает HTML-шаблон, статику и API.
- Данные проекта хранятся в памяти на клиенте.
- Импорт/экспорт выполняется на клиенте; сервер нужен как платформа приложения.
- При желании можно добавить серверные эндпоинты для проверки формата или будущего сохранения в БД.

### Модули frontend
- `projectStore` — текущее состояние проекта.
- `treeView` — дерево задач слева.
- `ganttView` — временная шкала справа.
- `taskEditor` — модальное окно редактирования.
- `dependencyManager` — создание, удаление и валидация связей.
- `fileManager` — экспорт и импорт JSON.
- `historyManager` — undo/redo.

### Модули backend
- `app.py` / `main.py` — запуск приложения.
- `routes/ui.py` — выдача страниц.
- `routes/api.py` — служебные API, если понадобятся.
- `schemas/project.py` — схемы проекта и валидация.

## Правила валидации
- `title` обязателен для всех элементов.
- Для `task` дата начала и окончания обязательны.
- Для `milestone` используется одна дата; `start_date` и `end_date` могут быть одинаковыми.
- `end_date` не может быть раньше `start_date`.
- Нельзя создать циклическую зависимость.
- Нельзя сделать зависимость элемента от самого себя.
- При переносе элемента внутрь самого себя или своего потомка операция блокируется.

## Риски и спорные места
- Самая сложная часть MVP — корректное сочетание дерева, drag-and-drop, временной шкалы и dependency lines в одном интерфейсе; именно эти функции обычно определяют зрелость Gantt-компонента [1][5].
- Нужно заранее решить, допускается ли свободное вложение всех типов элементов или, например, веха не может иметь детей.
- Нужно определить логику пересчета дат родительской группы: автоматически по детям или вручную.
- Нужно решить, должен ли сдвиг задачи автоматически сдвигать зависимые задачи; многие Gantt-системы считают автоучет зависимостей полезным, но это уже шаг за пределы базового MVP [7].

## Открытые вопросы для уточнения перед разработкой
1. Нужен ли только один локальный пользователь или в будущем сразу закладывать многопользовательский режим?
2. Должны ли зависимости автоматически сдвигать последующие задачи?
3. Как считать даты группы: вручную или как минимум/максимум по дочерним элементам?
4. Нужны ли рабочие календари, выходные и праздничные дни уже в первой версии?
5. Нужно ли поле «приоритет» помимо статуса?
6. Нужен ли режим только чтения для просмотра плана?

## Краткое решение по реализации
Для первой версии лучше сделать одностраничное веб-приложение на Python + Bootstrap, где Python отвечает за раздачу UI и будущие API, а само состояние проекта живет на клиенте в JSON-модели. Это позволит быстро реализовать дерево, диаграмму, импорт/экспорт и редактирование, не усложняя MVP серверной многопользовательской логикой.
