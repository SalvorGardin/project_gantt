# GanttFlow

Документация проекта на 22 октября 2026 года, обновлена после исправления импорта, защиты сессии, PNG/JPEG и даты окончания в подсказке. Источник фактов — код репозитория; ограничения проверки указаны в [анализе](audit.md).

Приложение позволяет одному пользователю вести дорожную карту: дерево групп, задач и вех, сроки, зависимости, ответственные и прогресс. Работа идёт в браузере, сохранение — вручную в JSON. Серверного хранилища и совместного редактирования нет.

## Быстрый запуск и использование

В каталоге проекта запустить `python3 -m http.server 8000 --bind 127.0.0.1` и открыть `http://127.0.0.1:8000`. Это обычная раздача статических файлов, а не Python-backend приложения. Сборка и установка зависимостей приложения не нужны. Внешние библиотеки загружаются через интернет.

1. На стартовом экране создать проект, открыть демо или загрузить JSON.
2. Добавить группу, затем выбрать её и добавить задачи или вехи. Подзадача добавляется через контекстное меню элемента.
3. Двойным щелчком открыть редактор; перетаскиванием полосы менять сроки, её краями — длительность.
4. Перетянуть якорь между задачами для связи FS; двойным щелчком по связи выбрать другой тип.
5. «Сохранить» выгружает JSON для продолжения работы. PNG/JPEG предназначены для просмотра, восстановить проект из них нельзя.

Статус «Нет новых изменений» означает отсутствие правок после загрузки или последнего запуска скачивания JSON, а не подтверждение записи на диск. После скачивания проверьте файл в загрузках браузера. Сохранение формы применяет изменения к плану в памяти. Автоматического восстановления при следующем открытии нет.

## Работа с документацией

Основные `specs/` описывают поддерживаемое поведение на корректных входных данных, но не означают прохождение всех сценариев в браузере. Известные нарушения и непроверенные области перечислены отдельно в `audit.md`.

Перед изменением поведения создать папку `changes/<имя>/` с proposal, delta-спецификациями, design при необходимости и tasks. После реализации и проверки перенести требования в основные спецификации и архивировать изменение. Чистый рефакторинг описывать в design/tasks без выдуманных продуктовых требований.

Структура и `config.yaml` созданы вручную по официальной документации [OpenSpec](https://github.com/Fission-AI/OpenSpec/blob/main/docs/getting-started.md) и [настройки конфигурации](https://github.com/Fission-AI/OpenSpec/blob/main/docs/customization.md). CLI `openspec` не обнаружен в PATH; команды и навыки CLI не устанавливались. Когда CLI доступен, выполнить `openspec validate --all --strict`. Локальная структурная проверка не заменяет проверку CLI.

## Проверки и ограничения

Основные проверки без зависимостей: `node --test tests/project-file.test.cjs` (Node 18+). Дополнительный браузерный сценарий: `node tests/import-browser.cjs http://127.0.0.1:8000` при доступных Playwright и Chromium. Для существующей установки можно передать NODE_PATH и BROWSER_EXECUTABLE; зависимости приложения не меняются. Также можно передать file:// URL index.html.

50 автоматических проверок и браузерный сценарий прошли. Для этого этапа проверены HTTP и прямое открытие HTML, оба способа импорта, отмены, откат и повторный save/load. Повреждённые файлы, которые прежний валидатор пропускал, теперь отклоняются с указанием поля. Экспорт PNG/JPEG исправлен и проверен отдельно через file:// в Chromium. Запуск: `node tests/export-browser.cjs [URL]` с теми же настройками Playwright/Chromium; контрольные изображения — /tmp/gantt-export-check или EXPORT_OUTPUT_DIR.

Даты проверяются командой `node tests/dates-browser.cjs [URL]` с теми же настройками Playwright/Chromium. Проверка прошла в двух часовых поясах, включая переход на летнее время.
