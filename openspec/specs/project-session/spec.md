# Сессия проекта

## Purpose

Один открытый проект в памяти вкладки браузера, создание и переход к работе с планом.

## Requirements

### Requirement: Стартовый экран
Приложение SHALL предоставлять создание проекта, загрузку JSON и открытие демонстрационного плана.

#### Scenario: Открытие демо
- **WHEN** пользователь выбирает демонстрационный проект
- **THEN** стартовый экран скрывается и дерево с задачами и связями загружается в диаграмму.

### Requirement: Создание проекта
Приложение SHALL требовать непустое название и позволять указать описание нового проекта.

#### Scenario: Пустое название
- **WHEN** название после удаления крайних пробелов пусто
- **THEN** приложение сообщает об ошибке и не создаёт проект.

#### Scenario: Новый план
- **WHEN** пользователь подтверждает непустое название
- **THEN** создаётся проект с идентификатором, временными метками и пустыми списками элементов и связей.

### Requirement: Предупреждение об изменениях
Приложение SHALL помечать изменения после сохранения формы элемента, перемещения полосы, редактирования связи и сворачивания ветки и запрашивать предупреждение браузера при закрытии изменённого плана.

#### Scenario: Закрытие после редактирования задачи
- **WHEN** пользователь сохранил изменённую задачу в форме и закрывает вкладку до экспорта JSON
- **THEN** приложение показывает признак несохранённых изменений и активирует предупреждение beforeunload, если браузер его допускает.

Сохранение формы меняет память, а не файл.

### Requirement: Безопасная замена проекта
Приложение SHALL сохранять текущий план до окончательного подтверждения нового проекта или импорта и предупреждать о потере несохранённых изменений при замене.

#### Scenario: Отмена нового проекта
- **WHEN** пользователь открывает форму нового проекта и отменяет её
- **THEN** прежнее имя, дерево, связи и признак изменений сохраняются.

#### Scenario: Отмена импорта
- **WHEN** пользователь отказывается заменить изменённый проект
- **THEN** текущий план остаётся доступным без изменений.

### Requirement: Учёт имени и структуры
Приложение SHALL отмечать изменение имени и порядка/родителя элемента как несохранённое изменение.

#### Scenario: Изменено только имя
- **WHEN** пользователь меняет только название сохранённого проекта
- **THEN** появляется признак изменений и включается предупреждение при закрытии.

#### Scenario: Перенос строки
- **WHEN** пользователь меняет порядок или родителя элемента
- **THEN** план отмечается изменённым, а повторный импорт его экспорта восстанавливает фактический порядок и вложенность.

### Requirement: Новый проект не сохранён
Приложение SHALL отмечать только что созданный проект как несохранённый, даже если в нём пока нет задач.

#### Scenario: Пустой новый проект
- **WHEN** создание проекта завершено
- **THEN** отображается признак изменений и закрытие вкладки активирует предупреждение браузера.

### Requirement: Выбранный элемент в строке состояния
Приложение SHALL показывать актуальное название выбранного элемента как текст либо «Ничего не выбрано», не помечая один только выбор как изменение плана.

#### Scenario: Выбор и переименование
- **WHEN** пользователь выбирает элемент и затем меняет его название
- **THEN** строка состояния показывает выбранное название, затем обновлённое название; HTML-подобный текст не интерпретируется.

#### Scenario: Сброс выбора
- **WHEN** пользователь нажимает пустое место диаграммы, удаляет выбранный элемент или открывает другой проект
- **THEN** строка состояния показывает «Ничего не выбрано».

### Requirement: Фокус модального окна
Приложение SHALL помещать фокус в открытый диалог, удерживать Tab/Shift+Tab в верхнем диалоге и возвращать фокус инициатору после закрытия; если инициатор недоступен — в нижний диалог либо диаграмму.

#### Scenario: Вложенное подтверждение
- **WHEN** над редактором открыто подтверждение и пользователь нажимает Escape
- **THEN** закрывается только подтверждение, введённые данные редактора сохраняются и фокус возвращается к вызвавшей кнопке.

#### Scenario: Обычный диалог
- **WHEN** открыт редактор задачи, связи, импорт или новый проект
- **THEN** начальный фокус внутри окна, Tab/Shift+Tab не уходят в фон, Escape отменяет только верхнее окно; задержанный фокус не возвращается в закрытое окно.

### Requirement: Точные сообщения о сохранении
Приложение SHALL различать применение формы к плану и запуск скачивания JSON, не утверждая запись файла на диск без подтверждения браузера.

#### Scenario: Форма и скачивание
- **WHEN** пользователь применяет форму, затем запускает скачивание JSON
- **THEN** форма сообщает о применении изменений, скачивание — о запуске и необходимости проверить файл; чистый статус обозначает «Нет новых изменений», а ошибка не сбрасывает dirty.

### Requirement: Расположение действий проекта
Приложение SHALL показывать кнопки создания группы, задачи и вехи справа в строке состояния под хедером; хедер SHALL не содержать кнопку «Загрузить» и кнопки создания элементов.

#### Scenario: Работа с планом
- **WHEN** пользователь открывает проект
- **THEN** количество элементов и состояние находятся слева, кнопки создания справа, а нажатия открывают прежние формы соответствующего типа.

#### Scenario: Недостаточная ширина
- **WHEN** содержимое строки не помещается по ширине
- **THEN** строка увеличивает высоту и переносит содержимое без наложения кнопок на статус.

### Requirement: Правый край действий хедера
Приложение SHALL выравнивать блок от масштаба до переключателя темы по правому краю хедера с сохранением внутреннего отступа.

#### Scenario: Свободное место в хедере
- **WHEN** ширина окна превышает суммарную ширину элементов хедера
- **THEN** свободное место располагается перед масштабом, а последний элемент блока остаётся у правого внутреннего края.
