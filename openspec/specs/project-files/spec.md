# Файлы проекта

## Purpose

Перенос плана в JSON v1 и загрузка корректных файлов в браузере.

## Requirements

### Requirement: Экспорт JSON
Приложение SHALL выгружать метаданные открытого проекта, текущие элементы и связи в JSON с schema_version 1, сохраняя исходные названия и вычисляя sort_order по текущему порядку детей.

#### Scenario: Сохранение плана
- **WHEN** пользователь сохраняет открытый проект
- **THEN** браузер получает файл с суффиксом `_gantt.json`, именем из поля проекта и обновлённым updated_at; после успешного запуска скачивания признак изменений сбрасывается. Это не подтверждение записи файла на диск.

### Requirement: Базовая проверка импорта
Приложение SHALL принимать только числовую версию 1, объект project с корректным ID, массив items с корректными типами и полями; links при наличии обязан быть массивом. Неподдерживаемый файл отклоняется с указанием поля и причины.

#### Scenario: Более новая версия
- **WHEN** пользователь выбирает JSON с числовой schema_version 2
- **THEN** показывается ошибка несовместимой версии и загрузка не подтверждается.

#### Scenario: Предварительный просмотр
- **WHEN** корректный файл выбран через верхнюю панель
- **THEN** перед заменой плана показываются имя, версия, число элементов и связей; пользователь может отменить импорт.

#### Scenario: Импорт со стартового экрана
- **WHEN** корректный файл выбран на стартовом экране
- **THEN** план загружается без отдельного предварительного просмотра.

### Requirement: Представление дат в JSON
Приложение SHALL сохранять календарные даты YYYY-MM-DD; окончание обычной задачи в экспортируемом v1 является исключительной границей, а у вехи совпадает с началом.

#### Scenario: Однодневная задача
- **WHEN** в редакторе указаны начало и последний день 2026-10-22
- **THEN** экспорт содержит начало 2026-10-22 и окончание 2026-10-23.

### Requirement: Целостность импортируемого проекта
Приложение SHALL проверять типы, поддерживаемую версию, даты, обязательные поля, уникальность ID, родителей, концы связей и отсутствие циклов до применения импортируемого плана.

#### Scenario: Повреждённый файл
- **WHEN** файл содержит некорректную дату, несуществующего родителя, дублирующийся ID, цикл или links другого типа
- **THEN** приложение сообщает причину и сохраняет текущий план, имя и признак изменений.

### Requirement: Атомарная замена плана
Приложение SHALL сохранять предыдущий план при ошибке применения подготовленного импорта.

#### Scenario: Ошибка диаграммы
- **WHEN** применение импортированных данных вызывает исключение после начала замены
- **THEN** предыдущие дерево, связи, метаданные и признак изменений восстанавливаются, а пользователь получает сообщение об ошибке.

### Requirement: Проверка перед сохранением
Приложение SHALL проверять экспортируемые данные по правилам v1 до скачивания и сохранять dirty-флаг при ошибке проверки или запуска скачивания.

#### Scenario: Ошибка сохранения
- **WHEN** текущее дерево не проходит проверку либо запуск скачивания бросает исключение
- **THEN** показывается ошибка, а признак изменений не сбрасывается.

### Requirement: Восстановительная копия
Приложение SHALL сохранять доступный для скачивания снимок предыдущего плана, если применение файла и откат диаграммы завершились исключениями.

#### Scenario: Повторная ошибка диаграммы
- **WHEN** ошибка загрузки сопровождается ошибкой отката
- **THEN** пользователь получает инструкцию нажать «Сохранить», и эта кнопка выгружает предыдущий план, а не частично загруженные данные.

### Requirement: Актуальность чтения файла
Приложение SHALL игнорировать результат устаревшего чтения после выбора другого файла или успешной замены проекта.

#### Scenario: Файлы прочитаны не по порядку
- **WHEN** чтение ранее выбранного файла заканчивается после выбора следующего
- **THEN** предыдущий результат не открывает предпросмотр и не заменяет план.
